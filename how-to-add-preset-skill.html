1. 概念：什么是系统预设 Skill

在 DeepSeek Harness 中，「系统预设 Skill」= 一个 bundled（内置）技能提供者包。它把一份固定的 Markdown 指令（技能正文）连同路由描述打包成一个 Cordis 插件，随产品一同发布，安装后即可被模型或用户直接使用，无需用户在本地技能目录里放置任何文件。

它有两种调用面（由 invocation 控制）：

调用面字段效果
模型可调用modelInvocable: true当用户请求命中技能描述时，模型会自动加载技能正文并遵循它作答。
用户可调用userInvocable: true用户可以在 / 技能选择器里直接手动选中它。

与之对照的还有另外两类技能来源：skill-filesystem（读取本地目录里的用户技能）和 runtime（运行时注册）。本文只讲系统预设这一类——即随包发布、source: 'bundled' 的提供者。

现成范例：仓库里已有三个同类包可作模板对照—— packages/skill/skill-badge（带图片资源）、 packages/skill/skill-office、 packages/skill/skill-parenting（最精简、纯文本正文，推荐作为起点）。

2. 架构与核心契约

技能系统是一个 能力接缝（capability seam），三个角色：

角色包职责
Service Definition（注册表）packages/skill/skill提供 ctx.skills，合并所有提供者的技能目录，处理重名去重（按 rank）。
Service Provider（提供者）skill-badge / skill-office / skill-filesystem / 你的新包实现 SkillProvider，向 ctx.skills.registerProvider() 注册。
Consumer（消费者）packages/skill/tool-skill把技能目录和加载到的正文渲染给模型。

2.1 你要实现的接口

新包只需实现 SkillProvider（来自 @deepseek-ai/dsh-skill）：

interface SkillProvider {
  readonly name: string                       // 注册表内唯一的提供者名，如 'dsh-parenting'
  readonly list: (options) => Promise<readonly SkillCandidate[] | SkillProviderObservation>
  readonly get:  (candidate, options) => Promise<SkillDefinition | undefined>
}

2.2 关键类型

类型 / 常量说明
BUNDLED_SKILL_RANK常量 = 600。内置提供者的标准优先级；重名技能 rank 低者胜出。
SkillCandidatelist() 返回的目录项：name / description / invocation / provider / source / rank / locator（+ 可选 resourceBase / metadata）。
SkillDefinitionget() 返回的完整定义 = Candidate 去掉 rank/locator，加上 content（Markdown 正文）。
SkillSource预设技能固定为 'bundled'。
SkillInvocationPolicy{ modelInvocable, userInvocable }。
命名规则：技能 name 必须是 kebab-case，正则 /^[a-z0-9]+(?:-[a-z0-9]+)*$/（如 parenting-master）。不合规会被注册表拒绝。

4. 分步实现指南

下面以新增一个名为 skill-foo、技能名 foo-master 的假想技能为例，逐步演示。把 foo 换成你的技能标识即可。

  1. 1

    创建包目录结构

    在 packages/skill/ 下新建 skill-foo/，最终结构如下：

    packages/skill/skill-foo/ ├── assets/ │ └── foo-master.md # 技能正文（Markdown） ├── src/ │ └── index.ts # 插件入口 + 提供者 ├── tests/ │ └── skill-foo.spec.ts # 单元测试 ├── package.json ├── tsconfig.json ├── README.md ├── README.zh.md └── README.i18n.yaml # 由生成器写入
  2. 2

    编写技能正文

    assets/foo-master.md

    这是模型加载技能后真正遵循的指令正文。用 Markdown 写清「身份定位、输出结构、能力边界」等。它通过 import.meta.url 相对路径读取，因此必须放在 assets/ 且随包发布。

你是……（角色、立场、覆盖范围、能力边界）

## 2. 输出结构
| 板块 | 要求 |
|---|---|
| … | … |
    参考：packages/skill/skill-parenting/assets/parenting-master.md 是一份结构完整的范例（身份/边界三段式/输出结构表格）。
  3. 3

    实现插件入口与提供者

    src/index.ts

    这是核心文件。它导出 Cordis 插件三要素 name / inject / apply，并在 apply 里把一个不可变的 SkillProvider 注册到 ctx.skills。

    /**
 * Bundled `foo-master` skill provider.
 *
 * @module @deepseek-ai/dsh-skill-foo
 */

import { readFile } from 'node:fs/promises'
import type { Context } from '@deepseek-ai/cordis'
import {
  BUNDLED_SKILL_RANK,
  type SkillCandidate,
  type SkillDefinition,
  type SkillProvider,
} from '@deepseek-ai/dsh-skill'

const PROVIDER_NAME = 'dsh-foo'
const SKILL_BODY_URL = new URL('../assets/foo-master.md', import.meta.url)
const INVOCATION = { modelInvocable: true, userInvocable: true } as const

// 这段描述同时驱动「模型自动路由」和「/ 选择器展示」，要写清「做什么 + 何时用」。
const DESCRIPTION = 'Foo 大师：……当用户咨询……时使用。只做建议，不做……'

const CANDIDATE: SkillCandidate = {
  name: 'foo-master',
  description: DESCRIPTION,
  invocation: INVOCATION,
  provider: PROVIDER_NAME,
  source: 'bundled',
  rank: BUNDLED_SKILL_RANK,
  locator: SKILL_BODY_URL,
}

const provider: SkillProvider = {
  name: PROVIDER_NAME,
  list: () => Promise.resolve([CANDIDATE]),
  async get(_candidate): Promise<SkillDefinition> {
    return {
      name: CANDIDATE.name,
      description: CANDIDATE.description,
      invocation: CANDIDATE.invocation,
      provider: CANDIDATE.provider,
      source: CANDIDATE.source,
      content: await readFile(SKILL_BODY_URL, 'utf8'),
    }
  },
}

/** Cordis plugin name. */
export const name = 'skill-foo'
/** Service required by the bundled provider. */
export const inject = ['skills']

/** Register the bundled `foo-master` provider on `ctx.skills`. */
export function apply(ctx: Context): void {
  ctx.skills.registerProvider(() => provider)
}

    如果技能正文引用了图片等相对资源

    需额外提供 resourceBase（参考 skill-badge），让加载器能解析正文里的相对路径：

    import { fileURLToPath } from 'node:url'
const RESOURCE_BASE = {
  kind: 'directory',
  path: fileURLToPath(new URL('../assets/', import.meta.url)),
} as const
// 在 CANDIDATE 和 get() 返回值里都带上 resourceBase: RESOURCE_BASE
    要点：
    • name（插件名）与 PROVIDER_NAME（提供者名）是两个概念：插件名对应组合行的 id 前缀，提供者名是注册表内标识。
    • 每个导出（name/inject/apply）都要有简洁 JSDoc —— 仓库有 verify-export-jsdoc 闸门强制。
    • 提供者在 apply() 里同步注册；正文在每次 get() 时读取。

  6. 6

    编写单元测试

    tests/skill-foo.spec.ts

    验证三件事：注册后能列出、能按名加载到正文、卸载后消失。

    import { Context } from '@deepseek-ai/cordis'
import { describe, expect, it } from 'vitest'
import SkillRegistry from '@deepseek-ai/dsh-skill'
import * as SkillFoo from '@deepseek-ai/dsh-skill-foo'

describe('dsh-skill-foo', () => {
  it('registers and disposes the bundled foo-master skill', async () => {
    const ctx = new Context()
    await ctx.plugin(SkillRegistry)
    const fiber = await ctx.plugin(SkillFoo)

    const listed = await ctx.skills.list()
    expect(listed).toEqual([{
      name: 'foo-master',
      description: expect.stringContaining('Foo 大师'),
      invocation: { modelInvocable: true, userInvocable: true },
      provider: 'dsh-foo',
      source: 'bundled',
    }])

    const loaded = await ctx.skills.get('foo-master')
    expect(loaded?.content).toContain('身份与定位')  // 断言正文里的稳定字样
    expect(loaded?.invocation).toEqual({ modelInvocable: true, userInvocable: true })

    await fiber.dispose()
    expect(await ctx.skills.list()).toEqual([])
  })
})
    覆盖率闸门：packages/*/*/src 要求逐文件 100% 覆盖（pnpm run test:coverage）。提供者代码要保持精简，确保 list/get 两条路径都被测到。

    编写双语 README

    README.mdREADME.zh.mdREADME.i18n.yaml

    每个包都要有 README.md（英）与 README.zh.md（中），带 YAML front-matter（description + kind: "package-reference"），并遵循固定的小节结构（Summary / Use this package / Understand the implementation / Model Experience / Known Limitations / Dev Note）。

    最省事的做法：复制 skill-parenting 的两个 README，把 parenting 相关文字替换成你的技能，保持小节标题与锚点结构不变。然后运行配对生成器写入 README.i18n.yaml：

  8. 8

    接入 base bundle（默认启用）

    这一步决定技能是否「开箱即用」。系统预设技能挂在 base bundle——所有 base-backed profile（web / desktop / headless / cli）共享的核心层。

    8a. 组合行

    packages/bundle/base/cordis.patch.yml

    在 skill 分组里（skill / skill-filesystem / skill-badge 附近）新增一行。不加 disabled 即默认启用：

        - id: skill-foo
      name: '@deepseek-ai/dsh-skill-foo'

    对照：skill-badge 那行带了 disabled: true（默认关闭），而 skill-parenting 不带（默认开启）。按需选择。

    8b. bundle 依赖

    packages/bundle/base/package.json

    在 dependencies 里按字母序（skill 分组）新增：

        "@deepseek-ai/dsh-skill-foo": "workspace:*",
    为什么两处都要改：cordis.patch.yml 声明「组合时挂载这个插件」，package.json 声明「base bundle 运行时依赖这个包」。缺任一都会导致插件找不到 / 不被加载。仓库有 verify-cordis-config 闸门校验二者一致。

7. 常见坑与注意事项

坑 1 · 正文丢失：package.json 的 files 忘记加 "assets"，或 Python SDK 的 ASSET_GLOBS 没登记，会导致技能在打包产物里找不到正文（源码跑正常、装完崩）。这类问题在开发期不易发现，务必两处都改。
坑 2 · 只改一处装配：只加了 cordis.patch.yml 组合行却没加 base/package.json 依赖（或反之），会导致插件解析失败或不被加载。verify-cordis-config 会拦，但先自查更快。
坑 3 · 手改生成文件：docs/module-graph.*、docs/capability-seams.* 是生成器产物。手改会在 doc-sync 时被覆盖或判为 not-up-to-date。正确做法是改 gen-doc-graphs.ts 后重新生成。
关于「默认启用」与「可选 bundle」的区别：本指南的预设技能直接挂在 base bundle，属于核心层默认启用。skill-parenting 提交里还引入了另一套机制（OPTIONAL_BUNDLES + DEFAULT_ENABLED_OFFICIAL_BUNDLES，位于 packages/boot/app-boot/src/profile.ts），那是给「独立可选产品 bundle」（如 dsh-market）用的——它更重、涉及插件管理器 Official 分组。普通的系统预设技能不需要动 profile.ts，挂 base bundle 即可。
关于外部 npm 依赖：skill-parenting 是纯内置包，不引入任何外部 npm 依赖。若你的技能需要外部依赖（像 dsh-market 依赖 dshmarket），要额外注意 pnpm 供应链策略（minimumReleaseAge）与 peer 依赖对锁文件/打包收集器的影响——这属于更复杂的场景，建议优先保持技能「零外部依赖 + 纯 Markdown 正文」的最简形态。
最佳实践：直接以 packages/skill/skill-parenting/ 为模板整目录复制，改名 + 改正文 + 改描述，再按第 8~10 步接线。这是当前仓库里最精简、最标准的预设技能范例。
